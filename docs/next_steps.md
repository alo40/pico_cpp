# Phase 2: Data Analysis

## 2.1 Verify a real saved dataset

- [ ] Run `python3 scripts/log_vedirect.py` with the current flashed firmware.
- [ ] Record at least a short real session.
- [ ] Confirm `data/raw/` contains received serial data.
- [ ] Confirm `data/processed/` contains timestamped valid CSV records.
- [ ] Inspect the first and last rows.
- [ ] Confirm sequence progression.
- [ ] Verify Mac receive timestamps, units, and plausible values.
- [ ] Stop with Ctrl+C and verify both files remain valid.
- [ ] Confirm the saved CSV is usable as input for analysis.

The processed `timestamp` is generated by the Mac when the logger processes a
Pico row. It is not an MPPT hardware timestamp or Pico acquisition timestamp,
and adjacent values may contain unmeasured jitter from USB transport, macOS
scheduling, Python execution, and serial buffering.

## 2.2 First dataset inspection

- [ ] Create an analysis directory when implementation begins.
- [ ] Create a first inspection script.
- [ ] Read one processed CSV.
- [ ] Report sample count and recording duration.
- [ ] Calculate timestamp interval statistics.
- [ ] Detect sequence gaps.
- [ ] Detect duplicate sequences.
- [ ] Classify Pico sequence resets separately from gaps.
- [ ] Detect malformed or missing values.
- [ ] Report minimum, mean, and maximum measurements.

The Pico sequence is monotonic only within one firmware execution. Normal
progression (`102 -> 103`), gaps (`102 -> 104`), and resets (`523 -> 1`) must be
classified separately; a reset is not hundreds of missing samples.

Do not begin this implementation until a real short dataset has been verified.

## 2.4 Acquisition reliability before long datasets

- [ ] Add UART RX overflow detection after the first basic plots.
- [ ] Use the overflow count when assessing dataset reliability.

Dropped UART bytes can invalidate or lose complete VE.Direct blocks, so this
work should precede serious multi-hour or daylight-cycle acquisition.
